# PBA Dashboard — Functional & UX improvement (2026-10-15)

Baseline = the uploaded `pba-dashboard-live-main` repository (identical to the local source, plus 4 stale files: `components/tabs/Overview.jsx` (not imported anywhere) and `docs/PBA_v3.3/3.4/3.5_CHANGES.md`).
Scope: presentation, interaction and shared components only. No formula, threshold, weight, baseline or KPI definition was changed.

## A. Implementation summary

### Shared UI kit — `components/kit.jsx` (new)
- One badge vocabulary, always **symbol + text + colour**: `OpBadge` (▲ Perlu dicek · ⇄ Bisa dipindah · ✔ Aman · ? Belum bisa dinilai), `ReachBadge` (✔ / ✖ / ?), `ReasonBadge` (same palette as the map), `CondBadge` (group + detailed status), `EvBadge` (Terukur solid · Estimasi / Belum terverifikasi dashed with "≈"), `ModeBadge` (Estimasi model · Replay historis · Skenario hipotetis).
- Entity panel parts: `PanelHead` (status badges + one sentence) → `Facts` → `More` (secondary detail) → `NextActions` (only actions wired to a real workflow; a disabled action states why).
- `EtaBbt`: ETA vs BBT bar with the BBT line and a one-sentence verdict; island ETA is shown as indicative, never as "late by X".
- KPI tile (`components/Scorecards.jsx › Tile`): + `badge` slot, keyboard focus ring; now also used for the sandbox measures and the 5 outage outcome boxes ("X dari N site (Z%)").
- `BbtCell` (ui.jsx): estimated / unverified BBT values are prefixed "≈" (tooltip explains) — an estimate never reads as a measurement.
- `DataTable`: rows selectable with Enter **and Space**.
- Workspace: "Buka record site lengkap" became a secondary link (one primary action per panel).

### Navigation & cross-module consistency
- Secondary pages in MBP and BBS share one divider label: **Untuk analis**.
- Developer paths removed from operational tooltips (engine/…, thresholds.yaml, Config › key.path) — admin pages under Data & pengaturan keep them.
- Context carried across pages (existing shared `focus`): Coverage → Planning sandbox shows a "selected site" strip (ETA before → after, BBT); Coverage → BBS; BBS → Coverage ("Cek jangkauan MBP", P1/P2 only, opens the site's reach tab with the row selected); Battery Condition → Field Actions; Fleet → History (camp filter) and → Planning › move.

### Fleet Performance
- Status column = badge + short reason (sering telat / sibuk / menganggur / tanpa job …): busy and idle can no longer be confused.
- Panel restructured (status → sentence → facts → detail → next steps). New action **Tampilkan site-nya di peta** switches the map to Site mode with the camp's sites highlighted; **Evaluasi pemindahan** (not for camps that need data clean-up) opens Planning › move.
- Partial-data area: the factual sentence no longer prints "0 dari 0 … — dari —"; the double-risk tile says it is an indicative per-site check outside the KPI.

### Coverage & Site Explorer
- Tabs show "dari N P1/P2 (Z%)"; reason column uses `ReasonBadge` (+n when several reasons apply).
- Panel: reach + reason + priority badges, ETA vs BBT bar, BBT with evidence, 3 nearest camps with ✔/✖, next steps with explanations.
- Island rows: ETA − BBT marked "*" and sorted after road sites (value unchanged).
- Partial-data P1/P2 sites flagged "indikatif" in the header (count).

### Resource Planning
- **Sandbox no longer loses work**: one scenario per NOP kept in PlanTab while moving between questions or NOPs; only Reset or an explicit choice clears it. The sandbox card shows "n perubahan di sandbox".
- **Hand-over is predictable** (`lib/sandbox.js › applyProposal`): empty sandbox → applied; sandbox with changes → choice *Ganti skenario / Tambahkan ke skenario / Batal*. Added-unit ids never collide after a merge.
- Each question carries ModeBadges (units = model estimate; move = replay + model; outage = hypothetical scenario; sandbox = model + replay); the two sandbox measures carry their own badge.
- Loading placeholders for every lazily loaded planning tool.

### BBS
- Battery Condition and Field Actions tables use `CondBadge` / `EvBadge` (Field Actions shows the group; exact label in tooltip and CSV).
- One site panel for both pages: condition + evidence + BBS priority → action with its rule sentence → battery facts → PLN exposure (short labels, source note) → detail → next steps (*Lihat tindak lanjut* on Battery Condition, *Cek jangkauan MBP* for P1/P2).

## F. Deferred issues (not changed)
1. **Partial-data area reach**: the KPI reports reach N/A for AREA 4, while per-site reach (Explorer tabs, double risk) is still computed with the same rule. Now labelled "indikatif"; a policy decision is needed (hide or keep per-site results for partial areas).
2. **Reason overlap**: 28 (AREA 1: 20) not-reached sites carry more than one reason; one display reason by fixed order (shown with "+n").
3. **Sizing denominator** (road-reachable P1/P2) differs from the reach KPI denominator; its "battery < mobilisation" exclusion includes unknown-BBT sites (83 of 165 in AREA 1).
4. **Island ETA** is a road equivalent; sea logistics are not modelled.
5. **Stale repo files**: `components/tabs/Overview.jsx` and three old docs exist only in the live repo; delete in git if no longer needed.
6. Hardening (out of scope): auth is basic auth only; no audit trail for Config edits.
